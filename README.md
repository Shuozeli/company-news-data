Company News Data is a version-controlled publication artifact generated by
[company-feed-server](https://github.com/Shuozeli/company-feed-server). It
contains company-news metadata, normalized article text, lazy browser indexes,
full-text JSONL shards, and machine-readable contracts.

## Read one article in 30 seconds

The browser path begins with a small bootstrap and follows paths declared by
that same snapshot:

```bash
BASE="https://raw.githubusercontent.com/Shuozeli/company-news-data/main/"

INDEX="$(curl -fsSL "${BASE}index.json")"
RECENT_MANIFEST="$(printf '%s' "$INDEX" | jq -r '.paths.recent_manifest')"
FIRST_PAGE="$(
  curl -fsSL "${BASE}${RECENT_MANIFEST}" |
    jq -r '.pages[0].path'
)"
ITEM="$(
  curl -fsSL "${BASE}${FIRST_PAGE}" |
    jq -c '.items[0]'
)"

printf '%s\n' "$ITEM" | jq '{company_name, title, published_at, canonical_url}'
ARTICLE_PATH="$(printf '%s' "$ITEM" | jq -r '.article_path')"
curl -fsSL "${BASE}${ARTICLE_PATH}"
```

The same traversal uses only Python's standard library:

```python
import json
from urllib.parse import urljoin
from urllib.request import urlopen

BASE = "https://raw.githubusercontent.com/Shuozeli/company-news-data/main/"


def get_json(path):
    with urlopen(urljoin(BASE, path)) as response:
        return json.load(response)


index = get_json("index.json")
recent = get_json(index["paths"]["recent_manifest"])
page = get_json(recent["pages"][0]["path"])
item = page["items"][0]

print(item["company_name"], "—", item["title"])
with urlopen(urljoin(BASE, item["article_path"])) as response:
    article_markdown = response.read().decode("utf-8")
print(article_markdown[:1_000])
```

For category-first navigation, follow
`index.json -> paths.category_directory_manifest -> category.pages[].path`.
Each category page contains at most 100 company rows. A company row points to a
`company.json`, whose article index contains pages of at most 50 summaries.

## What is included

- [`index.json`](index.json): lightweight browser bootstrap and generation
  checkpoint.
- [`HEAD.json`](HEAD.json): canonical full-archive checkpoint.
- [`index/v1/current/recent/`](index/v1/current/recent/): newest-first summary
  pages.
- [`index/v1/current/companies/`](index/v1/current/companies/): bounded
  alphabetical company directory.
- [`index/v1/current/categories/`](index/v1/current/categories/): predefined
  universe-sector categories; companies without a sector are placed in
  `Uncategorized`.
- [`index/v1/current/partitions/`](index/v1/current/partitions/): full-text
  JSONL, partitioned by publication month and adaptively sharded.
- [`articles/v1/`](articles/v1/): readable Markdown plus a provenance and
  content-hash record for each article.

The maintained universe includes public and private companies. Display names
come from upstream universe records and may include security-class suffixes
such as “Common Stock” or “Ordinary Shares.” Treat `company_key`, not the
display name, as the archive identity.

## Methodology, freshness, and deduplication

The source service discovers operator-reviewed RSS, Atom, HTML, and browser
sources, normalizes observations, and hydrates article content when available.
The current export target uses the explicit `approved_public` publication
scope. Under that scope, non-private items from approved, currently valid
sources can be published even when the source-level
`public_export_allowed` flag is false.

“Approved” is an operator quality and source-status decision. It means a source
was accepted for this pipeline; it is **not** a copyright license, a
redistribution permission, an endorsement, or a grant by the publisher. See
[`CONTENT_RIGHTS.md`](CONTENT_RIGHTS.md) before reusing article text.

Records expose separate timestamps where available:

- `published_at`: publisher-supplied or normalized publication time;
- `first_seen_at`: first observation by this pipeline;
- `fetched_at`: fetch used by the current normalized record;
- `last_updated_at`: last source-record update; and
- `generated_at`: snapshot materialization time.

`document_id` is deterministic over the schema namespace, company key, and
normalized canonical URL. The source service groups observations by company
and canonical URL and prefers the best available normalized content. Git
commits record snapshot changes; the generation digest changes when exported
document or content identity changes.

## Known limitations

- Some records have no publisher date, summary, or extracted body text. Empty
  fields are represented explicitly rather than guessed.
- Extracted Markdown can retain publisher boilerplate or lose layout,
  interactive media, images, and script-rendered content.
- Websites, canonical URLs, and extraction recipes change. A previously good
  record does not guarantee that its source remains reachable.
- Category coverage depends on upstream universe metadata. Missing sectors are
  published as `Uncategorized`.
- Display names are not guaranteed legal names or unique names. Use
  `company_key` and article provenance when disambiguating companies.
- Source approval is not a rights determination. Third-party article text is
  not CC0 and is not relicensed by this repository.
- The static tree does not provide server-side search or filtering. The reader
  and other clients navigate bounded manifests; bulk search consumers ingest
  selected JSONL shards.

## Architecture and contracts

[`ARCHITECTURE.md`](ARCHITECTURE.md) describes identity, trees, adaptive
sharding, checkpoints, and compatibility. Canonical JSON Schemas use Draft
2020-12 under [`schemas/v1/`](schemas/v1/), and
[`openapi/openapi.json`](openapi/openapi.json) describes the OpenAPI 3.1 static
read paths.

Interactive consumers should start at `index.json`. Bulk consumers should
start at `HEAD.json`, resolve the root manifest, select month partitions, and
verify each referenced byte count and SHA-256 digest. Paths under `v1` preserve
field meaning; breaking type, required-field, or identity changes require a
new major path.

## Validation

The status badge at the top links to validation for the published `main`
snapshot. The validator checks JSON parsing, hashes, byte and record counts,
ordering, uniqueness, generation consistency, bounded navigation pages, and
record/article cross-references.

Maintainers and full-mirror consumers can run:

```bash
python3 scripts/validate_archive.py
```

Lightweight clients should avoid a full checkout and verify only the manifest
and shards they consume.
